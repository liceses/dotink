# check/ · 本地自查脚本（**不是验收门禁**）

```powershell
node --test check/core.mjs      # 10 项：公式 / 场 / 现象确定性 / 厂标数据 / 版本 / 文件表
node tools/check-links.mjs      # 文档与页面里的相对链接不许悬空
# 或者一条：npm run check
```

## 它守什么、不守什么

| 守得住（可计算的宣称） | 守不住 |
|---|---|
| 半径映射：`√` 是面积映射、线性不是（§3） | **好不好看** |
| 现象场库的**确定性**（同参数两个实例逐格相同）、值域、会动 | 点读不读得成点（要 1:1 看） |
| `markplate.js` 移植**正文 sha256 与上游一致** | 母题够不够大、构图对不对 |
| 47 家厂标数据完整（顺序 / 路径 / 名字不重） | 覆盖率够不够、净空失不失衡 |
| 版本号一致、文档无断链、入口文件都在 | 观感、节奏、有没有"糊成一片" |

## 为什么刻意**不进 CI**

视觉工作的最终验收是**人的眼睛**：把画布打开、**1:1** 看、把成片放一遍。
脚本只用来**定位问题**（"这块画布有没有墨"、"这条公式对不对"），
**不能用来签字** —— 这一条在库里已经有两次实测教训：

- `lab-field22`（四十七家厂标）：用"这块画布有没有墨"验了**两轮全过**，而页面在肉眼上是**空的**
  —— 纸面底纹与"每格一个小点"的底噪本身就贡献几万个墨点；
- 本包 `marks.html`：第一版"墨量"读数把**透明像素**（r=0）算成了墨 → 报 **100% 墨**，
  而那页在肉眼上什么都没有。

所以：**脚本不进 CI、不挡 PR**；要发版时，人按 [`STANDARD.md`](../STANDARD.md) §16 的验收口径走一遍。
