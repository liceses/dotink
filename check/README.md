# check/ · 本地自查脚本（**不是验收门禁**）

```powershell
node --test check/core.mjs        # 18 项：公式 / 场 / 现象确定性 / 厂标数据 / 拆件装配 / 整条管线 / 版本 / 文件表 / 页面装载顺序
node --test check/transition.mjs  # 21 项：五种场转场、端点 / 值域 / 种子 / seek 与倒放 / 源内存保护 / 编码校验 / 管线
node --test check/press.mjs       # 19 项：调色板与碰撞 / 单版≡单色 render / 确定性 / 分色与 TAC / 色数与漏色 / 漂移单调性 / 装载顺序无关 / t 归正 / 版名唯一
node tools/check-links.mjs        # 文档与页面里的相对链接、src 与 href 不许悬空
# 或者一条：npm run check（core.mjs + transition.mjs + press.mjs + 链接）
```

## 它守什么、不守什么

| 守得住（可计算的宣称） | 守不住 |
|---|---|
| 半径映射：`√` 是面积映射、线性不是（§3） | **好不好看** |
| 现象场库的**确定性**（同参数两个实例逐格相同）、值域、会动 | 点读不读得成点（要 1:1 看） |
| `markplate.js` 移植**正文 sha256 与上游一致** | 母题够不够大、构图对不对 |
| 47 家厂标数据完整（顺序 / 路径 / 名字不重） | 覆盖率够不够、净空失不失衡 |
| 版本号一致、文档无断链、入口文件都在、页面装载顺序正确 | 观感、节奏、有没有"糊成一片" |
| **拆件装配**：核心不认识 HUD、四个核件存在、`overlays` 只加墨不改场（假画布跑整条管线） | 叠加层的构图好不好看 |
| **多色版套印**：单版 ≡ 单色 `render`（逐字节）、调色板碰撞（四版实到 15 色）、分色端点、TAC 压得住且像素不越界、套印偏移可复现 | 套得"像不像印刷机"、漏色重影好不好看 |

### 关于 `press.mjs` 的两条口径

- **`fringe` / `platesPerInk` 只对同角度基准有意义。** 玫瑰斑（15/75/0/45）各版点位本来就不同，
  这两个数会天然偏低且**几乎不随 drift 变**；拿它跨角度比较会得出"套得很准"的错误结论。
  所以漂移单调性那条测试固定四版同角度 45°，只用玫瑰斑做反证（对齐时 `fringe` 就已 ~0.4）。
- **`press` 不再依赖 `fields.js` 生成每版相位**（曾经依赖，是条真 bug）。旧代码是
  `DotInk._mulberry32 || (() => () => 0.5)`，而 `_mulberry32` 由 `fields.js:159` 挂载：只装
  `render.js` + `press.js` 时兜底恒返回 0.5 → 四版相位固定成同一常数 → 四版整体平移，**版与版之间
  没有相对错位**，色数从 13 掉到 4、`fringe` 从 0.2608 掉到 0.1838，而且一句警告都没有 ——
  看着像"有偏移"，其实核心现象根本没发生。现在 `press.js:34` 自带一份**逐位相同**的私有
  `mulberry32`，装载顺序再也影响不到结果。`press.mjs` 有两条测试守它：
  「漂移真的在动」（装了 fields.js 的常规路径）与「装载顺序无关」（真的只装 render+press，
  并要求两条路径的 `reg` 表、`regPx`、`colors`、`fringe` **逐位相同**）。

## 为什么刻意**不进 CI**

视觉工作的最终验收是**人的眼睛**：把画布打开、**1:1** 看、把成片放一遍。
脚本只用来**定位问题**（"这块画布有没有墨"、"这条公式对不对"），
**不能用来签字** —— 这一条在库里已经有两次实测教训：

- `lab-field22`（四十七家厂标）：用"这块画布有没有墨"验了**两轮全过**，而页面在肉眼上是**空的**
  —— 纸面底纹与"每格一个小点"的底噪本身就贡献几万个墨点；
- 本包 `marks.html`：第一版"墨量"读数把**透明像素**（r=0）算成了墨 → 报 **100% 墨**，
  而那页在肉眼上什么都没有。

所以：**脚本不进 CI、不挡 PR**；要发版时，人按 [`STANDARD.md`](../STANDARD.md) §16 的验收口径走一遍。
