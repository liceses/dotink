规范是唯一真相

这一套东西只有一份判据：STANDARD.md。其余四册（现象、厂标、转场、套印）都是它的推论 —— 每一册里能算的都写成了脚本，能在断网的机器上重跑一遍。

所以「看着对」不算通过。签字的必须是人的眼睛，脚本只负责把不该签字的东西挡在前面。

check/press.mjs · 与 M1–M3 不可互套

三条主判据

先问「这一屏的墨是在铺面，还是在勾线」，再选模式。选错模式，判据会把对的画面判死。

模式管什么门限状态
M1 网点模式：点要读成点 点距 : 点径（中位）≥ 3 : 1
点径 < 点距 / 2		 实测固化
M2 面场模式：点当面用 区域覆盖率 ≥ 8%
可见地板 ≥ 2% · 天花板 ≤ 55%		 实测固化
M3 结构线刻：点只落在结构上 报出结构处的局部覆盖率
不用整区 ≥8% 判它，必须 1:1 看一眼		 待标定

另外两条所有模式共用： 墨量预算（装饰墨 : 信息墨 ≤ 1:1，目标 ≤ 0.33:1）、 1-bit 纪律（compose() 之后非墨即纸，灰阶像素必须是 0）。

怎么自己验收

跑一遍

npm run check
# = node --test check/core.mjs check/transition.mjs
#   check/press.mjs check/theme.mjs check/site.mjs
#   && node tools/build-theme.mjs --check
#   && node tools/build-site.mjs --check
#   && node tools/check-links.mjs

当前基线：全部通过。条数会随页面增加， 以命令自己的输出为准。这些都不进 CI —— check/README.md 写明了理由：签字的是人的眼睛。

配色与站点骨架

node --test check/theme.mjs   # 令牌 / 对比度 / 零漂移
node --test check/site.mjs    # 导航 / 元信息 / 无孤儿页
node tools/build-theme.mjs --check
node tools/build-site.mjs --check

生成件不进 CI 的构建，但进仓： theme.css、theme.js 与每页的导航区都必须是「跑一遍生成器后的样子」。

边界（已知偏差）

标准里专门留了一节登记「这部分不属本标准」。改配色时最重要的一条是：

画布 vs 界面

  • 画布的墨与纸是硬令牌，标准套逐位等于 [12,13,14] / [242,243,242]
  • 站点的界面色（纸底、辅助灰、描线）从来不是标准条款
  • 五套 edition 的画布也能换 —— 但它们不是标准套，登记在 §11 的偏差账里

两套判据不可互套

  • M1 / M2 / M3 在套印层恒假：它量的是单版覆盖率与点距:点径
  • 套印层一帧里叠着 N 张版，得用 P1–P4（badPixels / tac / colors / 每版有墨）
  • 两边都跑一遍也不能互相担保
规范只约束画面；站点界面是 DOM，不在此列。 标准原文 配色说明 包说明 GitHub
